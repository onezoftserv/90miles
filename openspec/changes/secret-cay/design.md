# Design

## Context

See proposal.md for why. What exists on `main` today, and what shapes the approach:

- A run has one island. `GameShell._build_run` builds `sandbar_island.tscn` and nothing swaps islands while keeping players, so the cay can only be reached in a dev scene until crossing and arrival exist. The runner's `escape-routes` change (unmerged, `C:/Users/liann/src/90miles-sdk/wt/escape-routes`) adds the raft build site, `raft_site_glyph`, `route_ids` and `CrossingStub`, which ends the run when riders leave and marks a rider's body `left_island`. It edits `island_layout_data.gd`, `island_layout.gd`, `sandbar_island.gd`, `sandbar.tres`, `coop_session.gd` and `game_shell.gd`, so this change starts after it is merged and archived.
- `SandbarIsland` declares `@export var layout = preload(sandbar.tres)` and then builds `built`, `terrain` and `bounds` in member initializers. Those run when the script instance is created, before a packed scene applies a stored `layout` override, so today a scene that sets another layout still builds the sandbar. `furnish()` always adds a `Workbench`, at cell (-1, -1) when the layout has none.
- No code lists island layouts: `GameShell` preloads `sandbar_island.tscn` directly, and the content catalog only registers the `islands` folder.
- `IslandLayout.reachable_from` returns which cells are reachable, not how far. Its `WALKABLE` set is beach, dune, scrub and shallows, so deep water is never walked but shallows are.
- `WorldItem` forces `hold_time_s = 0` and draws one 6×6 rect for every item. It has no synchronizer: the spawn payload (name, item id, count, position) is all a client gets, and `CoopSession.spawn_pickup(item_id, count, at)` carries nothing else. Interactions run only on the host (`player.gd` runs `_update_interaction` where the world is authoritative), within 1 tile, so a client cannot claim a pick-up it did not reach.
- Inventories live on the host and replicate to every peer through `PlayerNet`, so a client knows what its own player carries.
- `CoopSession.player_removed(peer_id, last_position)` fires on the host when a dropped client's 90 s are up, and the body is freed right after. No code drops anything yet.
- `CoopSession.show_bubble` is a local call with a 2.5 s bubble; it cannot show a 100–200 character note to every peer.
- `ItemData.spawn_weight` defaults to 1.0 and is what an `ITEM_TAG` spawn picks by; `TextData` placement defaults to `min_island` 1 and `max_per_run` 1 (0 means unlimited). Left at the defaults, a secret item could be drawn by tag loot or text placement.
- `test_data_classes.gd` asserts 36 data classes and 12 content folders. Tuning resources (`CraftingTuning`, `SurvivalTuning`) live in `game/scripts/components/` outside that count, and the content validator only checks the content folders. Enums are append-only (`.tres` files store integers); `ItemTag` ends at `MEAT`, `Capability` at `POWER_SOURCE`. `balsero-lore` appends `Vessel` values, a different enum.
- `RunHud` (`game/scenes/ui/run_hud.gd` + `.tscn`, with `bind(session, local_peer_id, solo)`) is on `main` and every `ui-shell` task is ticked, but no ui-shell spec is archived yet: the HUD budget (meters top-left, day phase top-centre, teammates top-right, centre and bottom band clear) lives in the active `ui-shell` change. The needle's place is therefore a requirement of `secret-cay`. The dev playgrounds (`coop_playground.tscn`) carry only a `MetersHud`.

## Goals / Non-Goals

**Goals:**
- Every number in data: `secret_tuning.tres`, and the reveal radius on each item. Which items are the two pieces is data too.
- Every behaviour in the specs is a GUT test with exact numbers, with 1 player offline first (`test_secret_hunt_solo.gd`, `test_secret_cay_solo.gd`), then host plus client (`test_secret_net.gd`).
- The host alone places, picks up and opens; concealment and the needle are drawn locally from state every peer already has.
- Nothing changes in a real run: a solo or hosted run from the title is exactly what it was.

**Non-Goals:**
- Placing the pieces in real runs, the crossing to the cay, *Seguir la aguja*, wearing the hat, the cross-run unlock, reading panels (see "Later").
- Party-scoped conditions, an item drop or give action, a profanity setting, an inventory UI.
- Art: placeholder rects and colours until the asset audit (TASKS.md §11).

## Decisions

### 1. Data, not code
- `DataEnums.ItemTag.SECRET` appended after `MEAT`; `DataEnums.Capability.POINT_TO_SECRET` appended after `POWER_SOURCE`. The needle shows for any carried item with that capability, and `SecretPlan`, `SecretHunt` and the map's text read the two piece ids from the tuning, so no script names `brujula_rota` or `mapa_sin_norte`.
- `ItemData.conceal_radius_tiles: float = 0.0`. Above 0 the item is concealed on the ground and revealed within that radius; the two pieces set 3. This is the only home of the reveal radius: the critic's split made concealment a numeric item field, and a second copy in the tuning file would be two homes for one number. *Rejected:* a `concealed: bool` plus a radius in the tuning (the bool carries no number, so a future item could not hide differently).
- `SECRET` does one job: exclusion from discovery, maps, markers, AI context, item-tag spawns and found-text placement. It goes on all four items, each with `spawn_weight = 0`; a new content-validator rule rejects an item tagged `SECRET` whose `spawn_weight` is above 0. The cay carries `IslandLayoutData.secret = true`. Concealment and the needle's target come from `conceal_radius_tiles`, not from the tag, so the hat and the note are secret without being hidden or pointed at. *Rejected:* one tag for concealment, needle target and exclusion (tagging the hat would hide it and pull the needle to it; not tagging it would let the AI context carry it).
- `SecretRules.is_secret(entry) -> bool` and `SecretRules.without_secrets(entries: Array) -> Array` (`game/scripts/secret/secret_rules.gd`) are the one shared check and filter every later system calls.
- `IslandLayoutData` gains `off_graph: bool`, `secret: bool`, `chest_glyph: String`, `chest_item_id: StringName` (a reference to `items`, checked by the validator through `get_reference_fields`), `decor_glyphs: Dictionary[String, StringName]` (glyph to a decor id: `embers`, `cigar_smoke`, `drag_mark`, `cut_line`, `post`) and `decor_colors: Dictionary[StringName, Color]` (decor id to its placeholder colour). `_draw` looks each decor cell's colour up and never switches on an id, so a new decor kind on a later handmade island is a data edit; textures replace the colours at the asset audit. No new class in `game/scripts/data/` and no new folder, so `test_data_classes` keeps 36 and 12; only its field samples may need the new field types.
- `SecretTuning` (`game/scripts/components/secret_tuning.gd`, a `Resource` like `CraftingTuning`) and `game/resources/secret_tuning.tres` hold: `map_item_id` `mapa_sin_norte`, `compass_item_id` `brujula_rota`, `run_chance` 0.33, `index_min` 2, `index_max` 5, `shimmer_period_s` 6.0, `shimmer_length_s` 0.75 (inside the accepted 0.5–1.0 s), `concealed_pickup_hold_s` 1.5, `band_edges_tiles` [40, 20, 11, 6] (decision 5), `band_wobble_deg` [90, 45, 20], `spin_turns_per_s` 0.5, `chest_hold_s` 1.0, `note_base_s` 6.0, `note_per_char_s` 0.05, `spot_percentile_min` 0.50, `spot_percentile_max` 0.85, `spot_fallback_percentile_min` 0.25, `spot_fallback_percentile_max` 1.0, `spot_feature_min_tiles` 4, `spot_feature_max_tiles` 10, `spot_feature_kinds` [`palm`, `pickup`, `tide_pool`, `workbench`, `raft_site`], `roll_salt` (an int), and `spot_hints_es` / `spot_hints_en` (spot kind to the noun phrase that fills the map's landmark slot, plus `default`; the phrases are in `docs/ITEMS.md` "Secret items"). The tuning is not content, so the validator does not see its two item ids; `test_secret_data.gd` checks that both resolve in the catalog, that the compass id has `POINT_TO_SECRET` and that both have a reveal radius of 3.

### 2. The existence roll is a pure planner
`SecretPlan.roll(run_seed: int, tuning: SecretTuning) -> Dictionary` (`game/scripts/secret/secret_plan.gd`): its own `RandomNumberGenerator` seeded from `hash([run_seed, tuning.roll_salt])`, one `randf() < run_chance`, then two distinct indices drawn from `index_min..index_max`, the first for `map_item_id` and the second for `compass_item_id`. Its own stream means shipping it never shifts any other roll made from the same run seed. It is built and tested now because the owner's frequency decision is part of this capability's contract, but nothing in a real run calls it until island-generation owns the run seed; whether seeded and daily runs call it at all is open question 3. Indices 2–5 exist on every path (sandbar, coast, 3–5 mid/far, final) and are never the final approach, so a pick by index can never be skipped. *Rejected:* two independent item rolls (at 25% each both appear in about 6% of runs); SPD's per-floor "1 in (cap − depth)" roll (same job, harder to reason about when every path passes 2–5).

### 3. Hiding spots
`IslandLayout.walk_distances_from(start) -> Dictionary[Vector2i, int]` is a breadth-first search over the same `WALKABLE` set as `reachable_from` (never deep water; shallows still connect areas). `IslandLayout.hiding_spots(tuning) -> Array[Vector2i]` measures from the landing, which is the layout's solo spawn cell. Candidates are land cells (`WALKABLE` minus shallows: beach, dune, scrub), and the percentiles are taken over the reachable land cells' distances only. The features are the cells of the kinds in `spot_feature_kinds`: palms, non-secret pick-ups, tide pools, the workbench and the raft site (POIs join the list when they exist at runtime). A strict spot lies between `spot_percentile_min` and `spot_percentile_max`, 4–10 tiles in a straight line from the nearest feature, and on no feature or spawn cell. When the strict list is empty the rule relaxes in order until a list is not: the band widens to the fallback band (25th–100th percentile), then the feature-distance limit is dropped, then any reachable land cell that is not a feature or spawn cell is taken. Only a layout with no reachable land beyond its features and spawns returns nothing, and the layout check reports that as a problem. `IslandLayout.spot_kind(cell)` returns the nearest feature's kind (`palm`, the pick-up's `group` such as `flotsam`, `hut`, `beach`, `dune`, `tide_pool`, `workbench` or `raft_site`). The host picks a spot with `rng.randi_range` over the list; in real runs an island holds a single piece, and the dev hunt picks the map first, then the compass from the rest.

Checked by hand on the sandbar (582 reachable cells, 339 of them land): almost every land cell there is within 4 tiles of a palm, pick-up or tide pool, so the strict rule over land gives no cell (7 at a 3-tile minimum). Over all walkable cells it would have picked mostly shallows, which is why candidates and percentiles are land only. Pieces never go on the sandbar (index 1), but a coast island as crowded would land on the fallback, which is a normal path, not an error. The dev hunt layout is drawn sparser, so its strict list holds at least 2 land cells. *Adapted from* Brogue's far-from-origin quartile bound; the critic showed a pure far-quarter rule puts pieces exactly where nobody walks, so the band is 50th–85th. The 4–10 tiles near a feature is our own rule, from the critic. *Rejected:* a `one_cell` glyph field (it serves only a dev layout; real placement is a rule).

### 4. Concealment, shimmer and the hold on WorldItem
`WorldItem` reads its `ItemData` from `GameState.content` when it enters the tree. With `conceal_radius_tiles > 0`: each frame it checks the session's player bodies (host-simulated on the host, interpolated on clients) and sets a local `revealed` when any is within the radius, by straight-line distance in tiles; `_draw` draws the normal look when revealed, the shimmer glyph while `fmod(time + shimmer_phase_s, shimmer_period_s) < shimmer_length_s`, and nothing otherwise. `shimmer_phase_s` defaults to a value from a hash of the node name, so items do not blink together, and a test can set it; peers need not agree on shimmer timing. The interactable's hold is `concealed_pickup_hold_s` for such items and stays 0 for others, as the crafting-inventory delta's "Pick-up" requirement now says. The concealed look draws nothing, not a decoy decal. *Rejected:* host-owned revealed state over an RPC (no channel exists, it adds traffic, and the spawn payload already gives every client the position, so it would protect nothing); inert decoy decals over the island (nothing else on our islands draws such marks, so a lone decal is a beacon; Brogue's secret door works because it copies walls that are everywhere). The spec says plainly that a modified client can find the pieces.

`WorldItem` also emits `taken(by: PlayerBody, item_id: StringName)` on the host before it frees itself, so the hunt can react to the map being picked up.

### 5. The needle
`CompassNeedle` (`game/scenes/ui/compass_needle.gd` + `.tscn`, a 24×24 `Control`) is added to `run_hud.tscn` anchored top-centre directly under the day-phase label, and bound in `RunHud.bind` to the local peer only. Each frame it checks the local body's inventory for an item with `POINT_TO_SECRET`; without one it hides. Target: the nearest `WorldItem` with `conceal_radius_tiles > 0` in the session, else the island's `Chest` when not opened, else none (spin at `spin_turns_per_s`). Angle: `atan2` from the local body to the target, plus a wobble `sin(t · ω) · amplitude` where the amplitude comes from the band; it ignores north entirely. Distance is the straight line between the carrier's and the target's positions, in tiles, the same metric as the reveal radius. Beyond the first edge it spins; inside the last edge it holds still and ticks. It emits `rattled` once on crossing into the first edge and re-arms when the distance goes back beyond it; `AudioManager` plays the cue when assets exist. The cay's bearing during a crossing waits for the crossing scene.

The edges come from our own view and reveal radius: 40 tiles is the width of the 640 px view, so the needle wakes about one screen away from its target; 20 is half that width, the farthest a target can be and still be on screen to the left or right; 11 is half the 360 px view's height (22.5 tiles), so within it the target is on screen in any direction; 6 is twice the 3-tile reveal radius, a few steps from revealing the piece. On the cay (48×27, landing south, chest at the north tip) the chest is well inside the outer edge from the landing. *Rejected:* a needle on every peer (the carrier calling out is part of the co-op play, as SPD's compass is personal UI); bands that change the needle's speed only (harder to read on a 24 px sprite than a wobble that narrows).

### 6. The island scene takes any layout
`SandbarIsland.layout` gets a setter that rebuilds `built`, `terrain` and `bounds`; `_init()` builds once from the default, so a packed-scene override or a code assignment before `add_child` rebuilds from the right file. `furnish()` adds the workbench only when `built.workbench.x >= 0`, adds the `Chest` when the layout has a chest cell, and `_draw` draws the decor cells in their data colours. The class keeps its name for now; renaming it to something like `HandmadeIsland` touches files `escape-routes` also edits and is left to a later cleanup. *Alternative:* `@onready` builds (works for `GameShell`, which reads `terrain` after `add_child`, but a dev scene or test that reads `built` before entering the tree would see nothing; the setter covers both). The guard is `test_handmade_layouts.gd`, which instances `sandbar_island.tscn` with the cay layout and checks its size, palms, coconuts, spawns and the missing workbench.

`IslandLayouts.numbered(catalog: ContentCatalog) -> Array[IslandLayoutData]` (new, `game/scripts/levels/island_layouts.gd`) is the one listing of the layouts a run may use as numbered islands: every layout in the catalog's `islands` folder except those with `off_graph`. Nothing in a run calls it until island-generation builds the run graph, but it is the single home of the off-graph rule, and that work must list islands through it.

### 7. The chest
`Chest` (`game/scenes/structures/chest.gd` + `.tscn`, an `Interactable` with `chest_hold_s`) is created in `furnish()` on every peer under the fixed name `Chest`, like `HutWorkbench`, so an RPC reaches the same path everywhere. Its `_on_interacted` runs on the host only: if not opened, it picks an entry from the note's `TextData.entries` by `weight` (`pick_mode` RANDOM_ONE), spawns the layout's `chest_item_id` through `CoopSession.spawn_pickup` one cell south of the chest, and calls `receive_state.rpc(true, entry_id)`. `receive_state` is `@rpc("authority", "call_local", "reliable")` and returns at once unless the sender is the host (`multiplayer.get_remote_sender_id() == 1`, or 0 for the local call on the host). The host connects `CoopSession.player_spawned` and, when the chest is open, calls `receive_state.rpc_id(peer_id, true, entry_id)` with a `live = false` flag so the late joiner's chest is open with the same entry but no label pops up. The chest has no health, no theft hook and no burn hook, so it cannot be broken, burned, moved or looted. *Rejected:* the `escape-routes` `BuildSite.receive_state` pattern as-is (it never sends state to a peer that joins later); placing the chest through the pick-up spawner (it is a level structure, not an item).

### 8. The note and the map's text on a HUD label (stopgap)
`NoteLabel` (`game/scenes/ui/note_label.gd`, in `run_hud.tscn` under the needle's place, top-centre, at most 360 px wide, wrapped, in the HUD's small font, clear of the meters and the teammate list) shows a string for `note_base_s + note_per_char_s × length`. On a live `receive_state`, each peer reads the entry's body in its own language (Spanish unless English is set) and its soft variant once a profanity setting exists (until then the full text; the five entries have no swears, so their soft bodies stay empty, which `TextEntryData` reads as already clean). The map uses the same label: the dev hunt's `SecretHunt` node (`game/scripts/secret/secret_hunt.gd`, added under the session at a fixed name on every peer) places the pieces named by `map_item_id` and `compass_item_id` on the host, remembers the compass's spot kind, connects to the map's `taken` signal and calls `show_map_text.rpc(spot_kind)` (authority, call_local, host-only sender). The map's description has a landmark slot, `{pista}`, in both languages; each peer fills it with `spot_hints_<lang>[spot_kind]`, or the `default` phrase for a kind with none. The reading panel (npcs-dialogue) replaces both. *Rejected:* `show_bubble` (local only, 2.5 s, sized for a quick-chat phrase); a RANDOM_ONE pick on each peer (players would read different notes); a fixed palm in the map's text with the hint appended (it would draw a palm next to a hint naming the flotsam).

The note goes in the chest through the layout's `chest_item_id`, which bends the content model's "PoiData.loot is the only home of text placement". The sandbar's planned first bottle note faces the same choice; when POIs get a runtime, both move to `PoiData.loot` together.

### 9. A leaver's secret items
In `CoopSession._remove_player`, on the host, before the body is erased and freed, every inventory slot whose item carries `SECRET` is laid down with `spawn_pickup(item_id, count, last_position)`. A body with `left_island` set (a rider who already left by a route, from `escape-routes`) is skipped: its items left with it, and what a disconnect at sea does belongs to the crossing change. Then `player_removed` fires as today. This is the "inventory can be dropped there" hook the coop-networking spec already names, limited to secret items until a general drop exists. A dropped piece is concealed again like any piece; the needle of whoever holds the compass still finds the map. *Rejected:* putting the piece back on its first hiding spot (the party knows where their teammate stood, not where the piece first lay).

### 10. The cay layout
`game/resources/islands/cayo_sin_norte.tres`, 48×27 (the camera needs at least 40×23 for 640×360): a sand and scrub teardrop of about 200 land cells, 2 cells of reef shallows, deep water around. South: the landing beach with the solo spawn `S` and co-op spawns `1234` within 5 tiles of each other (the crossing spec's arrival scatter). Waist: the lean-to (`shade_glyphs`) with the hat's pick-up on one of its cells, the warm embers, the smoking cigar stub, the knife beside the embers, 2 rain cups, 3 palms holding 7 coconuts. East cove: the raft site `B`, `route_ids [raft]` (its only route, as island-generation's "Escape routes" now allows for off-graph layouts), and driftwood, inner tubes and rope on the sand, at least the raft recipe's inputs (today 6, 2 and 3, read from `recipes/raft.tres` by the test). A drag mark runs from the camp to the shallows, where a post holds a cut mooring line. North tip: the chest `X` on the land (non-shallows) cell farthest by walking from `S`, measured with `walk_distances_from` over `WALKABLE`; on a tie any cell at the greatest distance will do, and the test checks the chest's distance is the land maximum. `off_graph = true`, `secret = true`, `chest_item_id = nota_llegaste_tarde`, no workbench, no tide pool, every pick-up glyph `respawn = NEVER`. No creature, patrol or set piece: nothing spawns them on a handmade layout today, and the off-graph rule keeps generation away.

### 11. Dev scenes
`game/scenes/dev/secret_hunt_playground.tscn` and `secret_cay_playground.tscn` follow `coop_playground`'s `--solo`, `--host[=port]` and `--join=address[:port]` arguments and panel, build a `CoopSession` and a `SandbarIsland` with their layout, and print `secret:` status lines for headless checks. Unlike `coop_playground`, each instances `run_hud.tscn` and calls `RunHud.bind(session, local peer id, solo)` once the local player spawns, as `GameShell._enter_run` does, so the needle and the note label are on screen. The hunt uses `game/scenes/dev/secret_hunt_layout.tres` (outside `resources/`, so the catalog never lists it): a mid-island-sized beach and scrub cay with palms, flotsam, beach and dune pick-ups and two tide pools, drawn sparse enough that the strict hiding-spot rule yields at least 2 land cells, and a fixed dev seed that `SecretHunt` uses to place both pieces. The cay scene has a `--with-pieces` flag that gives the first player the compass and the map, for checking the needle and the chest by hand. A finding log prints how long the player took to find each piece, for tuning.

### 12. Tests (TDD order in tasks.md)
`test_secret_data.gd` (tuning values and piece ids, the four items with spawn weight 0, enum positions, the cay's flags, the shared check and filter), `test_secret_plan.gd` (roll), `test_island_layout.gd` additions (walking distances, hiding spots and their fallback, spot kind, chest and decor cells), `test_handmade_layouts.gd` (scene takes any layout, the numbered listing), `test_world_item_conceal.gd`, `test_compass_needle.gd`, `test_chest.gd`, `test_secret_hunt_solo.gd` (pieces, the hold, the map's hint, needle bands on the hunt layout), `test_secret_cay_solo.gd` (chest once, note, hat, drink and eat through `use_for`, leave alone by raft, with the pieces put in the inventory first), `test_secret_net.gd` (same spots, reveal by a teammate, one chest opening, late joiner, one hat, a leaver's pieces, a rider who already left), `test_secret_dev_scenes.gd`, plus the content validator and its new `SECRET` spawn-weight rule.

## Open Questions

None of these changes what this change builds; each must be answered before the "Later" work it names.

1. **One live level or split play in v1** (repo review item 16, open). With one live level, *Seguir la aguja* redirects the whole island's exit: every route off that island lands on the cay. With split play (the current escape-routes "Split parties" text), the redirect is decided when the first rider departs and fixes the destination for everyone still on the island, and the cay must stay active until the last rider arrives or dies.
2. **Who chooses *Seguir la aguja* in co-op** (the host, a vote, or the first rider), and whether that choice fixes the destination for riders who leave later. Solo: the one player chooses.
3. **Seeded and daily runs.** Do they roll the secret at all? Clients regenerate islands from the seed, so every client and every daily player could compute where the pieces lie. Seeded runs already never unlock keepsakes.
4. **Exits for companions and vessel-less routes.** El Viejo Tomás refuses rafts and boards, and the cay's built exit is a raft. Swim, turtle and dolphin arrivals bring no vessel to relaunch, and binoculars-and-swim assumes a visible destination. Options: limit the redirect to vessel routes, give the cay a non-raft exit (a skiff to repair), or have Tomás refuse the detour with a handwritten line.
5. **The cay crossing's distance band and threats**, and what happens when Gulf Stream drift reaches its 40-tile cap on the way to or from the cay (the crossing spec skips to a harder chain).
